# 公開スキル方針（public skills policy）

このリポジトリは、個人が複数案件で再利用しているエージェントスキルを、公開可能な形に
一般化して置く場所である。本ファイルは公開物の位置づけ・互換性・禁止事項・由来を定める。
個々の手順は各 `SKILL.md` を正本とする。

## 1. 位置づけ

- 対象は **Codex CLI / Claude Code / OpenCode** で使える portable な `SKILL.md` と、
  任意のエージェント別メタデータ（例: `agents/openai.yaml`）。
- 内容は**汎用**に書く。特定の案件・評価条件・作業記録・実行基盤の設定を前提にしない。
- スキルは判断を変える非自明な手順だけを置く。既存機能で足りる手順を重複追加しない。
- 特定の provider / model を汎用方針や汎用スキルへ**固定しない**。選択は利用側に委ねる。

## 2. 互換性の意味（過大な主張をしない）

「Codex / Claude Code / OpenCode 互換」とは、**同じ `SKILL.md`（と任意のメタデータ）を
各エージェントのスキル機構で読み込める**という意味である。次を意味しない。

- ランタイム、バックエンド、ツール集合、モデル、権限設定が同一であること。
- すべてのスキルが 3 エージェントで同じ挙動・同じ出力になること。
- CLI や外部ツールの版差を吸収すること（版差は各 `SKILL.md` の版確認で扱う）。

本ファイルの追加は**リポジトリ全体の監査を意味しない**。適用対象は新規追加・更新する
ファイルであり、既存ファイルの内容を一括で保証するものではない。検証も合成サンプルに
対するもので、実データに対する一般保証ではない。

## 3. 禁止する情報（private data prohibition）

公開するコード・ドキュメント・テスト・サンプルに、次を**含めない**。

| 種別 | 例 |
| --- | --- |
| 実ログ・会話 | 実際のセッション JSONL、transcript、エクスポート、DB 内容、生の実行結果 |
| 個人名 | 案件・会話・作業記録に登場する実名や通称（公開参照に必要なアカウント名は除く） |
| 実在のパス・利用者 | 実在の絶対パスやホームディレクトリ（実ユーザー名を含む）、ホスト名、社内共有パス |
| 内部識別子 | 非公開のリポジトリ名・プロジェクト名・タスク ID・ブランチ名・Issue 番号・組織名 |
| 内部 URL | 社内 wiki、ダッシュボード、チャット、トラッカー、非公開 API の URL |
| 実データ由来 fixture | 実データをコピーした fixture、実在の識別子を含むサンプル |
| 画像 | 実画面・実ログ・顧客情報を含むスクリーンショット |
| 秘密情報 | API キー、トークン、Cookie、認証情報、証明書、秘密鍵、個人情報 |

**許可されるもの**: `/path/to/repo`、`~/.codex/sessions`、`<uuid>.jsonl` のような
一般化したプレースホルダ、および公開標準の既定位置。合成した架空の識別子も可。
禁止対象は**実在の値**であり、プレースホルダや公開仕様のパスではない。

**人物の扱い**: 公開アカウント名（上流の maintainer、公開 Issue の投稿者、公開ドキュメントの
著者など）は、公開参照として必要な範囲で残してよい。公開済みであることは再掲の理由にならず、
必要最小限にとどめる。判断は「公開情報か」「再掲が必要か」で行い、
実在の名前一覧（denylist）を公開ソースへ置かない。削除した private な文字列を、
テスト・fixture・レビュー報告へ証拠としてコピーしない。

**公開 PR への添付禁止**: 実ログ・実結果・実パスを含む証跡を、公開 PR の本文・コメント・
添付ファイルへ貼らない。コミット前スキャンだけでは不十分で、PR 側の貼り付けも対象に
確認する。

## 4. サンプルと再現性

- 例・fixture・テストは**合成データのみ**で作り、第三者が同じ手順で**再現**できる形にする。
- プレースホルダを含む例は、意味の等しい合成値に置き換えて検証してよい。独立に導いた
  期待値（終了コード、出力形式など）を載せること自体は制限しない。
- 汎用コマンドの例示のたびに新しい承認や必須テストループを要求しない。実行済みの結果と、
  未確認の推測を区別して書く。

## 5. 由来・ライセンス・正本

- 他リポジトリのコードや文書を適応・引用する場合は、上流の**ライセンス**と**帰属**を保持し、
  `LICENSE` / ヘッダ / README の記載を削除・改変しない。スキル個別の `LICENSE` があれば
  それを優先する。
- 各スキルは手順の**正本**（source of truth）を明示する。外部 CLI が正本の場合は仕様を
  複製せず、版確認と配布元への参照を持つ。
- 上流更新へ追従するときは差分の意図を記録し、独自の一般化（固有名の置換など）を
  上流へ混入させない。

## 6. 利用者の権限を保つ

- スキルは手順と判断材料を提供する。**ワークフロー・確認項目・完了条件の最終決定は
  利用者にある**。利用者が指定した手順や検証をスキルの都合で置き換えない。
- スキル利用に**新しい承認ステップを追加しない**。既存の権限・承認・安全確認を
  増やしたり省略したりしない。
- 破壊的操作・公開・送信の可否は、利用者と実行環境の既存ポリシーに従う。

## 7. 公開前チェック（最小）

1. §3 の実在情報（実パス、内部識別子、内部 URL、秘密情報）を機械的に走査する。
   走査は手掛かりであり、0 件を安全宣言にしない。
2. 例と fixture が合成データで、実行して再現できることを確認する。
3. 上流由来ファイルのライセンス・帰属・正本、および §2 の互換性記述を確認する。
4. 公開境界（差分、例、docs、metadata、commit message、PR 本文・コメント）を面として点検する手順は
   [`skills/public-repository-privacy-review/SKILL.md`](../skills/public-repository-privacy-review/SKILL.md)。
   この点検は承認ゲートではなく、公開可否の決定は利用者と既存ポリシーに残る。
