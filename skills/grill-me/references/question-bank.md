# 質問の枝と frontier の計算

## 設計木 → frontier の手順

1. 決定ノードを枝（下の表）から洗い出す。
2. ノード間に依存を張る（例: 「データの正本」が決まらないと「欠落時の契約」は聞けない）。
3. 前提がすべて確定済みのノード集合が **frontier**。
4. frontier を優先順位（上位・ブロッキング・不可逆を先）で並べ、**上限 N** までを今回のラウンドにする。
5. 依存で送った質問は「次ラウンド送り」と明記する（黙って落とさない）。

## 枝の種

| 枝 | 問いの例 | よくある依存 |
| :--- | :--- | :--- |
| 目的 | 成功をどう測るか / 誰の何が良くなるか / やらないことは何か | スコープの前提 |
| スコープ | どこまで今回やるか / 境界の外は何か | 目的の確定後 |
| データ | 入力の正本はどれか / 欠落・不正時の契約 / 再現性の担保 | スコープの確定後 |
| 失敗 | 失敗の定義 / 失敗時に何を残すか / ロールバック | データ契約の確定後 |
| 運用 | 誰が回すか / 頻度 / 監視と通知 / コスト上限 | スコープの確定後 |
| 成功指標 | 合格ラインの数値 / 比較対象 / いつ測るか | 目的・データの確定後 |
| リスク | 最悪ケース / 影響範囲 / 緩和策 | 失敗・運用の確定後 |
| 代替案 | 他候補 / 却下理由 / 再評価条件 | 目的の確定後 |
| 依存 | 外部チーム・API・データの約束 / 破られた場合 | スコープ・運用の確定後 |
| 不可逆 | 後から戻せない決定か / 戻すコスト | 常に上位優先 |

## ラウンド出力テンプレート

```text
N 問で出します（上限。変更可）。今回の frontier は <件数> 件、次ラウンド送りは <件数> 件です。

【目的】
Q1（目的）: <質問。複数案の比較でもよい>
  なぜ: <曖昧なままだと壊れること>
  推奨: <推奨回答と理由 1 行>

次ラウンド送り:
- <データ契約の質問>（理由: 「正本」の決定に依存）
```
