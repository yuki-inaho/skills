# start-with-workdocs

### 【LLMエージェント向け指示】

**最優先ルール:**
*   **作業書の確認:** 作業書/workdocのパスについて示せ。
*   **作業の逐次実行:** 作業書のチェックリストを上から順に**1つずつ**実行せよ。
*   **完了報告:** 1つのチェックボックスを `[x]` に変更したら、その**直後に**作業記録を更新せよ。
*   **継続:** 全てのチェックリストが `[x]` になるまで、このプロセスを繰り返せ。

**作業フロー:**
1.  **時刻記録:** 作業開始前に `date` コマンドで現在時刻を確認し、作業記録に記載する。
2.  **タスク実行:** チェックリストの次の未完了タスク `[ ]` を1つだけ選び、実行する。
3.  **チェック完了:** タスクが完了したら、チェックボックスを `[x]` に変更する。
4.  **記録更新:** `workdoc` の作業記録テーブルに、実行したタスク内容と結果（成功/失敗、発見事項など）を追記する。
5.  **繰り返し:** 全てのチェックリストが `[x]` になるまで、ステップ2に戻る。
6.  **完了の定義の確認:** 全てのチェックリストが `[x]` になった場合、完了の定義欄のチェックリストを確認し、作業完了定義を満足しているかを確認する。


**定期的リマインダー (N=40行動ごと):**
N回の行動ごとに、以下の文章を**一字一句変えずに**表示し、自分自身に注意喚起せよ。また、出力と同時に行動カウントはリセットせよ。
> 「では、作業計画書兼記録書のチェックリストを細かく更新し、作業開始前に必ず date "+%Y-%m-%d %H:%M:%S %Z%z" コマンドで現在時刻を確認し、正確な日時を記録してください。詰まった場合は必要に応じてタスクを細分化して作業を再開し、行動カウントと注意事項を注意した上で作業継続してください。チェックリストがすべて埋まるまで作業を続け、表示後には必ず行動カウントをリセットしてください。行動カウントがリフレッシュされるタイミングでかならず作業記録を更新してください（状況報告）。行動カウントは行動のたびに明示的に出力してください。」

**重要事項:**
*   **細分化:** タスク遂行中に問題が発生した場合、タスクをより小さなステップに分割して対応せよ。
*   **停止禁止:** リマインダー確認後も、思考や作業を中断せず、シームレスに次のタスクを続行せよ。
*   **注意事項の遵守:** `workdoc`に記載された注意事項（DRY/KISS/SOLID原則など）を常に意識せよ。

## When to use

- 作業書（`temp/workdoc_<Mon><DD>-<YYYY>_*.md`）がすでにあり、そのチェックリストに沿って DoD まで作業を進めるとき。
- 作業書がまだ無い場合は、先に `write-workdoc-uv` で作成し、`review-written-workdoc` でレビュー・修正してから本スキルに入る。
- 使わない場面: 作業書を作るほどでもない単発の質問・小修正。

上の指示文は利用者指定の文面をそのまま採用しているため、`## Prerequisites` / `## Procedure` は置かない（手順は「作業フロー」、前提は「When to use」）。

## Verification

```bash
date "+%Y-%m-%d %H:%M:%S %Z%z"          # 作業記録に書く実時刻
grep -c -- '- \[ \]' temp/workdoc_*.md    # 未完了チェック数。完了時は 0
```

- 完了の定義欄の全観点が `[x]` で、各観点の証跡（コマンド出力・成果物パス）が作業記録にある。
- 作業記録の各行に上記 `date` で取得した実時刻が入っている。

## Failure handling

- チェック項目が大きすぎて1回で終わらない: 作業書に `手順 n-a`, `n-b` の小手順を追記してから実行する（勝手に省略しない）。
- 前提が崩れた（ファイル・依存・データが無い）: 暗黙の代替をせず、作業記録に証跡を残し、作業書に代替手順を明示してから進める。
