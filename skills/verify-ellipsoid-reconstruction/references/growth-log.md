# Evidence-backed workflow changes

## 2026-10-19: Separate arithmetic binding from metric meaning

**Observed limitation.** A prior independent task using this skill found two unsupported numerical claims that passed the original checker: a timing-success fraction used reconstruction counts, and a reconstruction-success fraction used the number of available estimates. Both fractions exactly matched the selected source pointers. The manual procedure detected the substitutions, so improving file/hash checks alone would not address the problem.

**Adopted change.** Add optional, hash-pinned metric contracts mapping a rate ID to exact count pointers, an explicit success predicate, failure treatment, threshold sources, denominator population, counted unit and independent sampling unit. Keep version-1 manifests accepted. Warn when a rate has no contract, when only claims were inspected, and when an expected run roster is absent. Compare a supplied roster with listed runs and retain failures in the record-count check. Keep the generic checker independent of particular scene seeds and result formats.

**Executed evidence.** Fifteen isolated regression tests passed, including the two self-consistent pointer substitutions, changed thresholds, omitted failure records, missing runs, and the distinction between object counts and scene-level independent sampling. The existing reporting adapter's 46 claims, 172 rates and six control cases retained their prior arithmetic outcomes. Adding reviewed contracts to the two earlier unsupported rate bindings produced two explicit pointer-contract errors. The official skill `quick_validate.py` passed. These are workflow tests, not new reconstruction-performance samples.

**Retained limits.** A consistently wrong author-supplied contract can still pass. Correct counts can accompany an incorrect prose conclusion about a threshold. The script therefore always leaves predicate implementation, scientific meaning, units, roster completeness, and registration chronology for independent review. A retrospective contract is reporting evidence, not preregistration. Mechanical success is not permission to publish a claim. A fresh agent must use the revised skill and raw candidate documents before broader adoption is claimed; record that result separately rather than assuming regression tests establish generalization.

**Independent use of this revision.** A fresh agent received this skill, a candidate manifest and a retrospective metric registry, with access only to their referenced original evidence. The checker rejected two inconsistent count bindings. A third candidate paired correct counts with an incorrect adoption statement and passed the checker; the independent reviewer rejected that prose claim. The reviewer recomputed all eight small-scene results and all 400 dense-scene object decisions using a separate unit-sphere tangent-circle projection, with a maximum heldout-error discrepancy below 8.1e-13 pixels. It also exercised invalid-start, missing-warm-start, nonconvergence and excluded-object boundaries while retaining the dense denominator. All 46 input hashes recorded by that review were unchanged at completion. This supports the combined contract-and-independent-review procedure on those tasks; it does not establish universal detection of semantic errors. After the trial, only trigger wording and an explicit Python invocation example were clarified; the validated checker behavior was unchanged.
