# 画像を直接注釈する

対象の定義と採点条件を案件側に残し、目視による回答作成・幾何確認・回答確定を分ける手順です。画像内容の正しさを幾何検査の合格で代用しません。

## When to use

- 原画像を直接見て、点・BBOX・ポリゴンのいずれか、または同じ領域に対応する組を作る。
- 見逃し、境界、遮蔽、座標変換を確認し、回答を確定してから参照答案で評価する。
- 使わない場面: 自動検出器の実行だけで足りる作業、参照答案の転記、採点仕様の変更。

## Prerequisites

- [案件契約](references/task-contract.md)を読み、対象・除外対象、可視部分と推定部分、点の意味、遮蔽分離、座標、上限、出力形式、既存の検査器・採点器を固定する。元の対象定義を優先し、外見の似た別概念へ置き換えない。
- 注釈担当が読める入力を許可リストで限定する。評価対象画像１枚と必要な定義・形式を基本とし、評価対象の参照答案、参照ラベル画像、参照者の note、期待個数、採点結果は渡さない。元の manifest 全体を渡してから「無視する」方法では分離にならない。
- 利用者が明示的に認めた別の例題は、案件契約で版を固定して加えてよい。例題の使用有無・ID・版を記録し、例題なしの試行と比較条件を混ぜない。
- 原画像を表示できる環境と、必要なら拡大表示・座標目盛りを用意する。表示できない場合は座標を推測して回答しない。

## Procedure

1. **１枚ずつ独立して見る。** 各画像の担当・推論入力を独立させ、先行する評価対象画像の回答や所見を次の担当へ混ぜない。同一の案件契約と許可された固定例題は共有できる。複数の評価対象画像を一枚の縮小一覧へ置き換えない。
2. **対象を定義と照合する。** 全体を見て対象候補と除外理由を確認し、曖昧な箇所だけ拡大する。切抜き・回転・縮尺を使ったら原画像へ戻す変換を記録する。
3. **形を決める。** 領域内部の点が求められる場合は確実な内点を置き、可視輪郭をたどり、最後に同じ領域へ近いBBOXを置く。点の役割が別なら案件定義に従う。遮蔽で離れた部分を結ぶか別 object にするか、見えない部分を推定するかは案件契約で決め、勝手に統合しない。
4. **初稿を保存して確認する。** 既存の形式検査器を実行し、必要な補助幾何検査を追加する。原画像と注釈を重ねた画像の両方を実際に見る。対象の取り違え、見逃し、余分な領域、境界の切り過ぎ・はみ出しを確認し、初稿・修正版・重畳図・変更理由を別々に残す。修正後にも両方を見直す。修正回数だけを改善の証拠にしない。
5. **全予定回答を確定する。** 予定画像IDを先に列挙し、未提出・不正・中断も記録する。入力、設定、全回答、形式・幾何の検査結果を指定して凍結し、確定時のSHA-256を別の実行記録へ保持する。確定後にファイルが変わっていないことを確認してから参照側を開示する。
6. **指定された採点を行う。** 参照画像、画素化、分母、画像間の集約方法を含め、利用者の採点器を正本として使う。幾何合否・画像上の品質・公式得点を別欄に記録し、都合のよい別指標へ置き換えない。参照を見て修正した場合は別試行にし、参照を見ていない評価と区別する。
7. **所見を証拠に結び付ける。** [観測記録](references/observations-template.md)に findings / tips / struggles を残す。参照を見る前の観測と採点後の所見を分け、観測・仮説・変更・再検証・適用範囲・未検証を区別する。モデルID、推論設定、終了理由は実行基盤の証跡から記録し、取得できなければ unknown / null にする。

### 補助コマンド

スキルのディレクトリから実行する合成例です。入力形式と凍結一覧は[案件契約](references/task-contract.md)にあります。実案件の寸法・上限・座標端点規約へ置き換えてください。

```bash
python3 scripts/annotation_run.py --help
python3 scripts/annotation_run.py geometry answer.json --x-max 64 --y-max 48 --point-location inside
python3 scripts/annotation_run.py overlay answer.json --image image.png --output inspection-01.svg --width 64 --height 48 --x-max 64 --y-max 48 --coordinate-frame image-edges --point-location inside
python3 scripts/annotation_run.py freeze run-plan.json --output frozen-run.json
python3 scripts/annotation_run.py verify frozen-run.json --sha256 "$FROZEN_SHA256"
```

`FROZEN_SHA256` には確定時に別途保持した値を指定します。補助は標準ライブラリのみで動作し、独自のJSON Schema検査や採点はしません。原点が左上で、座標下限が0の形式を扱います。別の規約やキー構造なら、案件側で対応を明記した補助入力を作り、提出回答そのものも凍結します。

## Verification

- `geometry` が終了コード0なら幾何エラーは検出されていない。警告は残し、既存検査器の判定と区別する。対象が正しい、見逃しがない、採点が高いという意味ではない。
- 重畳図には原画像、画像の幅・高さ、座標上限、端点規約が含まれる。描画先の画素座標と案件の正規化座標を混同しない。先頭・末尾の画素中心を指す規約を画像端へ置き換えない。
- 初稿と修正版が保存され、原画像・重畳図の確認記録と差分理由がある。曖昧さや未確認を消していない。
- `freeze` は全予定回答IDを残す。終了コード1でも不完全な記録は保存される。`verify` が0となるのは記録が完全かつ内容不変のときだけで、公式形式・意味の正しさは別途確認する。
- 別領域で実行していない再利用性を実証済みと書かない。複数領域の少数例で動いた場合も、その適用範囲までを報告する。

## Failure handling

- 自己交差・重複頂点・隣接辺の折返し: 原画像で輪郭順を見直す。自動的な並べ替えや凸包への置換で済ませない。
- BBOXの余白、領域の重複・接触、画素丸めで潰れる極小領域: 補助警告として残す。共有境界や遮蔽分離の規約を確認し、無条件に削除・統合しない。
- 座標や画像の向きが一致しない: 原画像の向き・寸法・変換を先に確かめる。表示だけ合わせて回答座標を放置しない。
- 回答確定後の削除・変更、参照の混入: その試行の独立性を報告し、元の記録を上書きせず別試行を作る。
- 実行できなかった工程: 未実行と記録する。検査予定や自己批評を実測結果に数えない。
