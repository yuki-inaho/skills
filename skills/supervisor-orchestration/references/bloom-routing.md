# Bloom ルーティング詳細

## 判断の芯

「**手順書があるか？**」だけを問う。ある → 実行係（L1〜L3）。ない → 思考係（L4〜L6）。

## 分類例

| 依頼 | レベル | 根拠 | 宛先 |
| :--- | :--- | :--- | :--- |
| この名前のファイルを探して | L1 | 検索手順が自明 | explore |
| このモジュールの責務を要約して | L2 | 読み取りのみ | explore |
| 規約どおりにテストを 1 本追加して | L3 | 手順が既知 | general（実行係） |
| 失敗の根本原因を特定して | L4 | 仮説検証が必要 | 思考係 |
| 2 案のどちらを採るか決めて | L5 | 判断 | 思考係 + 監督裁定 |
| 新機能の構成を設計して | L6 | 設計 | 思考係、統合は監督 |

## ブリーフ雛形

```text
目的: <1文>
役割: 実行係（手順に沿う） / 思考係（分析・設計）
成果物: <path>（完了条件: <検証可能な条件>）
証拠: 実行コマンド・引用・確認結果を成果物に含める
禁止: commit/push、スコープ外変更、PII の持ち出し、外部 API への送信
返信: findings / tips / struggles + 根拠 + 残リスク + 成果物パス（25 行以内）
```

## 並列化の原則

- ファイル所有権を重複させない（同時編集の競合を防ぐ）。
- フリーズポイント（全成果物が揃う点）までコミット係を起動しない。
- 依存関係は「直列」、独立作業は「並列」。迷ったら直列にする。
