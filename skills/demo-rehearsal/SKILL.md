# Demo Rehearsal

デモは「流れて終わり」では伝わらない。**秒単位の時間設計**と**受け手の証言**で改善する。

## 手順

### P — Plan（時間設計）

- 各区間について次を決める（台本としてファイル化する）:
  `操作` / `言うこと` / `意図` / `説明秒` / `理解待ち秒`（沈黙） / `キャプション`。
- 理解待ちの目安: 新しい概念 1 つにつき 5 秒、専門用語の言い換えが必要な区間は 15〜25 秒、
  図表を読む区間は 15〜25 秒。合計を提示予定時間の ±30% に収める。
- 短縮版（要点のみ）を 1 つ用意する。

### D — Do（リハーサルは headless 固定）

- リハーサルと本番で証跡の取得経路を揃える。ライブ提示のみ headed にする。
- 撮影枚数・所要時間を記録する。スクリーンショットが**同一画像になっていない**ことを
  サイズやハッシュの多様性で確認する（操作が効いていない検知）。

### C — Check（聴衆エージェント、各 1 体ずつ独立コンテキスト）

- ペルソナは [references/audience-personas.md](references/audience-personas.md) から選ぶ（既定 3 体）。
- 台本・要約・スクリーンショット一覧を渡し、次を返させる:
  1. 区間別の理解度 1〜5 と、分からなかった語・箇所
  2. 体感時間と、理解に要した推定秒
  3. 判断に不足する情報（無ければ「無し」）
  4. 誇張・隠蔽・再現不能な主張の指摘
- 記録は作業用一時ディレクトリにラウンド番号付きで残す。

### A — Act（最大 2 ラウンド）

- 2 体以上が同じ箇所で理解度 ≤ 3 なら、言葉・キャプション・順序を修正する。
- 数字の不整合（母数と内訳、定義の食い違い）は最優先で直す。
- 修正後、最大 1 回だけ再チェックして収束させる。収束しない場合は残課題として明記する。

## Verification

- スクリーンショット数が仕様どおりで、内容が互いに異なる（サイズ多様性で機械確認）。
- 実測時間が設計の ±30% に収まる。
- 聴衆評価の平均理解度 ≥ 4、かつ「判断に不足」が 0 件（未解決は明記）。
- 台本に「曖昧語・陳腐化した表現」が残っていない（横断 grep）。

## Failure handling

- 所要が短すぎる/一瞬で終わる: 台本の `理解待ち秒` を実測に合わせて増やす。自動進行の仕組みが無いなら作る。
- スクリーンショットが全部同じ: 操作フックが描画を更新していない。フックで即時再描画を呼ぶ。
- 聴衆評価が割れる: 2 ラウンドで打ち切り、対立点を明記して次回議題にする。
- 数字が説明と食い違う: 母数・定義を本編で明言し、内訳を必ず併記する。
