# start-work-with-docs

最新のユーザー指示と成果物を基準に、既存の作業書を使って作業を進める。
作業書は実行を助ける記録であり、追加の承認権限を持たない。

## 適用範囲

- ユーザーが作業書に沿った実行を求めたときに使う。適用されるリポジトリ指示を読み、使う作業書のパスを示す。
- 「作業書不要」「MVPを優先」「自走させる」などの新しい指示は古い計画より優先する。文書作成・レビューを自動的に前提条件へ追加しない。
- 厳密な逐次実行や記録頻度を今回のユーザーが指定した場合は従う。過去のテンプレートの指定を全タスク共通の規則にしない。

## 実行

1. 求められる実体成果物、完了条件、現在使える入力、必要な依存関係を把握する。未解決事項は、それが本当に止める操作と結び付ける。
2. 最初に利用可能な成果へ到達する経路を選ぶ。依存関係を守り、関連する実装・実行・確認を一つのまとまりとして進める。文書の掲載順やチェック数だけで実行順を決めない。
3. 許可済み範囲の通常の修正・再試行は担当者が続行する。チェック項目の細分化や新しいGOを、その都度の前提条件にしない。範囲・成果物・評価条件を変える必要がある場合は、既存の権限で判断できるかを確認し、必要な判断だけを求める。
4. 入力、ラベル、評価分割、実行設定など、結果の有効性を左右する前提と変更に必要なチェックを行う。成功後は、新しい変更・失敗・未解決の懸念がある場合に影響する範囲だけ再検証する。記録の誤字だけで有効な実行をやり直さない。
5. 成果が出た時点、重要な失敗、引き継ぎ、終了時に記録をまとめる。実行ログの時刻を利用できる。記録更新を次の実行の待ち条件にせず、必要な証跡は保持する。行動ごとのカウントや定型リマインダーは標準では出さない。

## 停止と完了

- ユーザーの停止指示、権限外の操作、既存データの破壊、誤った入力での実行などは対象操作を止める。安全に進められる独立した作業まで一律に止めない。
- 不意の既存差分は上書き・リセットしない。ジョブの状態が不明なら、再投入前に実プロセスと出力を確認して重複実行を防ぐ。
- 必要な成果物と確認結果で完了を判定する。チェックが埋まったこと、文書レビュー、準備用の短い試験を、本実行や品質達成の代わりにしない。
- 未達の要求を勝手に縮小しない。不要になった手順は理由付きで対象外にし、未完了の成果は未完了のまま報告する。
- 進捗は成果物の存在、実際の実行状態、測定値、残作業で示す。準備項目の完了率をユーザー成果の達成率に換算しない。所要時間の見込みには実測根拠を付け、不明なら不明とする。

## 最終報告

実体成果物のパス、得られた結果、実施した必要な確認、未達事項を報告する。
文書が要求された場合は、その更新先も示す。全項目を埋めるためだけの作業を追加しない。
