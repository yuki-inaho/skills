# Start Work With Docs

作業書を正本として、チェックリストを上から一項目ずつ実行する。実装や調査の結果を作業書へ即時記録し、チェックリストと完了の定義がすべて満たされるまで継続する。

## 開始時の確認

1. 実行中のエージェント（Codex、Claude Code、OpenCode など）を明示する。
2. リポジトリの `AGENTS.md`、`CODEX.md`、`CLAUDE.md` と参照先を確認する。
3. 作業書/workdocの絶対パスをユーザーへ示す。パスが与えられていない場合は `temp/` 等から候補を探し、採用理由を示す。
4. 作業書を読み、未完了チェックリスト、作業記録、完了の定義、注意事項を確認する。
5. 作業開始前に必ず次を実行し、取得した日時を作業記録へ記載する。

   ```bash
   date "+%Y-%m-%d %H:%M:%S %Z%z"
   ```

作業書に記載されていない目的・要件・閾値・評価指標を追加しない。必要な拡張が見つかった場合は、実装で隠さず作業書の停止条件として記録し、判断を求める。

## リマインダー間隔

- `N` はデフォルト `40` とする。
- ユーザーが `N=20`、`20行動ごと` のように正の整数を指定した場合、その値を採用する。
- 実行途中にユーザーがNを変更した場合、現在の行動記録を作業書へ記録し、カウンターを0へリセットして新しいNを適用する。
- 0、負数、非数値など無効な指定は採用せず、デフォルトまたは直前の有効値を維持し、理由を記録する。
- 作業に影響するコマンド、ファイル確認、編集、テスト、判定を1行動として数える。各行動の直後に `行動カウント: k/N` を出力する。
- `k` が `N` に達した時点で、次の文章を一字一句変更せずに表示し、直ちにカウンターを0へリセットする。その後の作業を中断せず続行する。

> 「では、作業計画書兼記録書のチェックリストを細かく更新し、作業開始前に必ず date "+%Y-%m-%d %H:%M:%S %Z%z" コマンドで現在時刻を確認し、正確な日時を記録してください。詰まった場合は必要に応じてタスクを細分化して作業を再開し、行動カウントと注意事項を注意した上で作業継続してください。チェックリストがすべて埋まるまで作業を続け、表示後には必ず行動カウントをリセットしてください。行動カウントがリフレッシュされるタイミングでかならず作業記録を更新してください（状況報告）。行動カウントは行動のたびに明示的に出力してください。」

## 逐次実行ループ

以下を、通常チェックリスト、サブチェックリスト、完了の定義の順に繰り返す。

1. 次の未完了 `[ ]` を上から**1つだけ**選ぶ。後続項目を先取りしない。
2. 実行前に次を短く示す。
   - 対象項目
   - 目的
   - 完了条件
   - 変更を許可するファイル範囲
3. 対象項目だけを実行する。必要なら作業書の注意事項に従って小さなサブタスクへ分割する。
4. 成功条件と、失敗・未達・想定外変更の有無を確認する。
5. 成功した場合、対象のチェックボックス**だけ**を `[x]` に変更する。
6. `[x]` へ変更した直後、同じ作業書の作業記録テーブルへ、日時・項目・実施内容・結果・証拠（コマンド、ファイル、テスト）を追記する。次の項目へ進む前にこの記録更新を完了する。
7. 失敗した場合はチェックボックスを `[ ]` のままにし、失敗原因、再現コマンド、未解決事項を作業記録へ追記する。必要なら小さなサブタスクを作業書へ追加するが、元の項目を完了扱いにしない。
8. 各行動の直後に行動カウントを明示し、N到達時のリマインダー処理を行う。

チェックボックスをまとめて変更しない。作業記録を後回しにしない。テストが失敗しているのに「完了」と記録しない。

## 検証と安全策

- リポジトリ固有の `just`、`uv`、テストコマンドなど、作業書が指定する標準経路を優先する。
- コマンド、作業ディレクトリ、変更ファイル、テスト結果を作業記録へ残す。
- 不意の既存差分を見つけたら、上書き・リセット・削除をせず、対象範囲を分離して記録する。
- `git reset --hard`、広範囲削除、秘密情報の出力、無断のcommit/pushを行わない。
- 診断依頼では修正せず、作業書が修正を明示している場合だけ変更する。
- 新しいハイパーパラメータ、評価閾値、ベースライン、最適化手法を作業書の承認なしに追加しない。

## 完了判定

通常チェックリストが全て `[x]` になったら、作業書の「完了の定義」またはDoDを確認する。DoD項目も上から一つずつ検証し、各項目を `[x]` にした直後に作業記録を更新する。

次の全条件を満たすまで完了報告しない。

- 通常チェックリストとDoDが全て `[x]`
- 実装差分、テスト結果、失敗時の扱いが作業記録にある
- 未解決事項と残存リスクが明示されている
- `git diff --check` と作業書指定の最終検証を実行済み
- ユーザーが要求した実体成果物（データ、画像、設定、メタデータ等）が実際の出力先に存在する。indexやsource pathだけで代替しない
- 要求を実装都合でmetadata-only、表示-only、または別の縮小スコープへ変更していない。変更が必要なら停止条件として記録し、承認を得る
- 未追跡差分を一括で取り込まず、目的別に分類し、ユーザー既存の変更を削除・上書きしていない

## 最終報告

完了時は、作業書のパス、完了した項目数、主要な変更、実行した検証、残存リスク、未完了項目（あれば）を報告する。未完了項目がある場合は完了とは表現せず、停止理由と再開条件を示す。
