# workdoc template reference

Use this as a starting point for a Japanese handoff, not a mandatory set of
tasks. The user may request a different location or a compact form. Default:
`temp/workdoc_<Mon><DD>-<YYYY>_<slug>.md`, using the actual date.

Retain enough detail for another agent to execute without the original chat.
Remove irrelevant sections; add detail where a real dependency or decision needs
it. Do not make this document a prerequisite when the user asks to proceed
without one. Preserve existing authorization; do not add per-step approvals.

## 3. 完了の定義

- [ ] <ユーザーが要求した実体成果物と内容が確認できる>
- [ ] <成果物に必要な検証・評価が完了し、結果と限界が示されている>
- [ ] <文書・引き継ぎが要求された場合、その必要な記録がある>

精度・速度などの達成が要求なら、実行成功や失敗の記録だけで達成扱いに
しない。実験実施と結果報告だけが依頼なら、性能未改善と実施完了を区別する。
調査・計画だけの依頼では、未実行の学習や評価まで完了にしない。

## 4. 作業記録

成果が出た時点、重要な失敗、引き継ぎ、終了時にまとめて記録する。
時刻は実行ログまたは実時計から取る。文書記入時刻をジョブ開始時刻に
置き換えない。通常の記録更新を次の実行の前提にしない。
